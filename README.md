# RestFlow 통합본

설치자·관리자·이용자 화면과 Android 앱은 RestFlow-Demo-Font 버전을 기반으로 합니다. Flask와 MariaDB에서 운영 정보, 출입 기록, 자동 환기와 팬 상태를 관리합니다.

## Windows 실행

1. Python 3.12와 MariaDB 10.11 이상을 설치하고 MariaDB 서비스를 실행합니다.
2. **START_DEMO.bat**을 실행합니다. 처음 실행하면 MariaDB 접속 정보를 묻습니다. 이미 만들어 둔 DB를 쓰거나, DB 생성 권한이 있는 계정으로 처음 설정할 수 있습니다.
3. 설치자 화면은 `http://127.0.0.1:8080/`, 이용자 화면은 `http://127.0.0.1:8080/user`입니다. 시청역 여성 구역의 운영 4/5칸과 혼잡도 보통을 확인할 수 있습니다. 장비 데이터와 팬 회신은 시연용 가상값입니다.
4. 실사용은 시연 서버를 종료한 뒤 **START_SERVER.bat**을 실행합니다. 시연과 실사용은 서로 다른 MariaDB 데이터베이스를 씁니다.
5. TMAP 지도·검색·길찾기를 쓰려면 원본 프로젝트의 설정을 이 프로젝트의 `mobile/.env.local`로 복사하거나, 서버에 `RESTFLOW_TMAP_MAP_KEY`와 필요에 따라 `RESTFLOW_TMAP_ROUTE_KEY`를 설정합니다. DB 설정을 다시 입력하려면 `py setup_mariadb.py`를 실행합니다.

Android 앱은 **START_APP.bat**을 통해 Expo Go에서 미리 볼 수 있습니다. `mobile/.env.example`을 `mobile/.env.local`로 복사하고 `EXPO_PUBLIC_RESTFLOW_URL`을 휴대폰에서 접속 가능한 서버 주소로 바꿉니다. LAN 접속 시 같은 Wi-Fi를 사용합니다. 웹 브라우저의 GPS는 HTTPS 또는 localhost가 필요하며, 앱은 자체 GPS 권한을 사용합니다.

## 역할별 설치 및 인계

- **설치자**가 서버 PC에서 장소·구역을 등록합니다. 장소 상세의 **모듈 추가**에서 구역 이름·유형, 운영 칸 수와 장치 ID를 입력합니다. 환기 제어 사용 여부까지 선택해 등록하면 연결 키가 기존 모듈 목록의 해당 행에 표시됩니다. ATOM Lite만 설치하면 센서 키만 발급됩니다. Raspberry Pi를 함께 설치하면 환기 제어를 켜고 두 키를 각 장비에 넣습니다. 기존 센서 모듈에 환기 제어기를 붙일 때는 등록 목록의 환기 추가를 사용합니다. 키를 재발급하면 연결된 장비 설정을 갱신해야 합니다. 삭제된 범위의 장비는 인증이 철회됩니다. 기존 기록과 연결된 ID는 보존되므로 새 연결에는 새 장치 ID를 사용합니다.
- **관리자**는 설치자가 전달한 장소 관리자 QR과 인계 코드로 비밀번호를 설정합니다. 운영 칸 수와 폐쇄 사유를 관리하고, 센서 상태·현재 습도·재실 추정·팬 명령 및 적용값을 확인합니다. 구역 운영 카드 아래에서 환기 설정을 펼칩니다. 자동 모드에서는 목표 습도와 무인 자동 절전(팬)을 저장하고, 수동 모드에서는 팬 출력을 0~100%로 지정합니다. 재실 상태가 불확실할 때는 현장에서 사람이 없음을 확인한 뒤 초기화할 수 있습니다.
- **이용자**는 웹 또는 앱에서 운영 칸 수, 혼잡도, 길찾기를 확인합니다. 지도와 목록의 혼잡 단계는 최근 10분 입장 건수 ÷ 운영 중인 칸 수를 기준으로 계산합니다. 칸당 1건 미만은 여유, 1건 이상 2건 미만은 보통, 2건 이상은 혼잡입니다. 운영 칸이 0이면 이용 불가입니다. 센서가 없거나 수신 상태를 확인할 수 없으면 정보 없음으로 표시합니다. 관련 구역의 측정값이 모두 있으면 합산하고, 시설 입구 센서만 있으면 시설 전체 혼잡도를 표시합니다.

## 실제 센서와 팬 설정

- ATOM Lite에 ToF와 DHT11을 연결합니다. `firmware/include/secrets.example.h`를 `secrets.h`로 복사한 뒤 Wi-Fi, HTTPS 주소, 서버 인증서, 장치 ID와 **ATOM Lite 키**를 설정합니다. PlatformIO에서 빌드·업로드하고 설치된 위치에서 ToF 거리와 입·퇴장 방향을 교정합니다.
- Raspberry Pi 4B에서 `raspberry_pi/README.md`를 따라 제어기를 설정합니다. 같은 장치 ID와 **Raspberry Pi 키**를 사용합니다. Pi의 GPIO18 PWM을 XY-MOS 입력에 연결하고, 5V 팬에는 정격에 맞는 별도 전원을 사용합니다. 현장 연결 전에 `--dry-run`으로 명령 수신을 확인할 수 있습니다.
- 자동 모드에서는 목표 습도부터 환기를 강화하고 목표보다 10%p 높은 습도(최대 100%)부터 최대 출력으로 전환합니다. 습도 강화와 무인 절전에는 기존 혼잡도·재실 판단을 사용합니다. 고습도에서는 환기가 우선입니다. 데이터가 신선하고 신뢰 가능한 무인 상태에서는 기본 5분 뒤 저출력으로 전환하고 15분 뒤 정지합니다. 재실 불확실 상태에서는 자동으로 정지하지 않으며, Pi가 서버와 통신하지 못할 경우 기본 60% 출력으로 전환합니다.
- 실제 장비는 HTTPS 주소를 사용합니다. 운영 배포에서는 Flask 앱을 운영 WSGI 서버와 HTTPS 프록시 뒤에서 실행하고 `RESTFLOW_PUBLIC_URL`에 실제 방문 주소를 지정합니다. 설치 화면은 서버 PC의 루프백 주소에서 엽니다. 실제 배선, 팬 정격·기동, 감지 방향과 Wi-Fi는 현장에서 확인합니다.

## 기존 웹 데이터 이전

원본 서버를 종료하고, 빈 실사용 MariaDB를 지정한 뒤 `py migrate_sqlite.py "C:\\경로\\restflow.sqlite3"`를 실행합니다. 시설 ID, 구역 ID, 운영 상태, 관리자 비밀번호 해시와 인계 정보를 복사합니다. 기존 QR을 계속 쓰려면 QR에 들어 있던 서버 주소와 포트를 유지해야 합니다. 이 도구는 Demo-Font의 SQLite를 읽습니다.

## 개발 및 검증

- `web-source`에서 `npm ci`와 `npm run build`를 실행한 뒤 `dist`를 `web/redesign`에 배치합니다. 이 ZIP에는 빌드된 웹이 포함되어 Windows에서 웹을 실행하는 데 npm이 필요하지 않습니다.
- MariaDB 접속은 `db_config.json` 또는 `RESTFLOW_DB_HOST`, `RESTFLOW_DB_PORT`, `RESTFLOW_DB_USER`, `RESTFLOW_DB_PASSWORD`, `RESTFLOW_DB_DATABASE`, `RESTFLOW_DB_DEMO_DATABASE`로 설정합니다.
- 전용 테스트 DB에서 `python -m unittest discover -s tests -p integration.py -v`를 실행합니다.
