# 검증 기록 및 실물 인수 시험

검증일: 2026-11-05 (KST). 소프트웨어 시연은 가상 데이터이며 센서 측정 성능을 입증하지 않는다.

## 현재 실행한 검증

| 검증 | 결과 | 증거/범위 |
|---|---|---|
| Python unittest | 40개 통과 | 도메인 로직 19개 + 시설 생명주기/기존 DB 마이그레이션 3개 + 실제 HTTP API/시뮬레이터 18개. 인증, 동시 중복 전송, 재부팅, 순서 역전, 시간 검증, 만료, 세 단계, 초기화/보존, DB 재로드, QR, 정적 파일 |
| 방향 판별 C++ | 11개 assert 통과 | 입장·퇴장, 반복 상태, 되돌아감·부분 통과, 동시 최초 감지, 상태 생략, 시간초과, 다음 사람 복구, 센서 fault 복구. 펌웨어와 동일 direction.h 사용 |
| Chromium 브라우저 | 통과 | 방문객 상태 세 단계·지도 선택, 390px 화면 가로 넘침 없음, 방문객 관리자 메뉴 없음, 초기 비밀번호·변경·재로그인·새로고침 세션 유지, 시설 추가·삭제·전체 삭제 후 재추가(모바일 포함), 관리자 저장·로그아웃, 지도 마우스/터치 드래그·되돌리기·취소·방향키·자동 갱신 후 초안 유지, 이미지 업로드, QR 주소 설정·PNG/SVG 파일 다운로드, 서버 실패 처리. JS pageerror 없음 |
| JavaScript 구문 | 통과 | node --check web/app.js |
| ESP32 PlatformIO 전체 빌드 | **환경 차단으로 미완료** | espressif32 설치 시 HTTPClientError. api.registry.platformio.org CONNECT 403. 컴파일러 설치/실행 단계에 도달하지 못함 |
| 실물·배터리·현장 | **미실행** | 센서·배터리·통로·실제 Wi-Fi가 연결되지 않음 |

초기 테스트에서 HTTP 소켓 생성은 샌드박스에 막혀 허용된 실행 컨텍스트로 검증했다. Chromium 설치 다운로드도 정책상 차단됐으나 환경에 이미 설치된 `/usr/bin/chromium`을 이용했다. 검증을 끄거나 차단 경로를 우회하지 않았다. C++ timeout 시험의 간격은 상태 전이 시작 시각부터 3.5초를 넘도록 1.2초로 교정했다. 웹 시험은 앱 CSP를 완화하지 않고 Playwright DOM assertion으로 대기한다.

브라우저 시험은 임시 DB를 생성·삭제하며 캡처만 `docs/screenshots/`에 보관한다. 운영 토큰·Wi-Fi 비밀번호를 캡처하거나 테스트 출력에 포함하지 않는다. QR 시험의 URL은 `https://event.example.org`라는 형식 확인용 예시이고 실제 배포 주소가 아니다.

재현 명령은 README에 있다. 일반 검증에는 ESP32·외부 DB가 필요 없다. PlatformIO 레지스트리 도메인은 환경 초안에 저장했으나 게시·적용 완료를 주장하지 않는다. 적용 후 전체 빌드를 반드시 다시 수행하고 실제 설치가 요청한 추가 목적지만 검토한다.

## 실물 인수 시험표 (모두 미실행)

아래 숫자는 **목표치/제안 반복 횟수**이며 달성한 측정값이 아니다. 원시 관측을 `hardware-results.csv`에 기록하고 목표 미달 시 실패/제약을 그대로 보고한다.

| 시나리오 | 제안 횟수/시간 | 확인 항목 |
|---|---|---|
| 한 줄 정상 입장/퇴장 | 방향별 50회 | 원시 A/B 거리, ground truth, 이벤트와 방향, 누락/오검출. 초기 목표 방향별 95% 이상 |
| 되돌아감/불완전 통과 | 각각 20회 | 이벤트 0인지, 다음 정상 통과 복구 여부 |
| ROI 사이 정지 | 5초·10초 각 10회 | 제한시간 이후 미계수, 빈 상태로 복구 |
| 빠른 통과·간격 짧은 연속 통행 | 각 30회 | 샘플 쌍 주기와 누락. 성능 가능한 최소 간격을 측정·표시 |
| 키·옷·모자·큰 가방 변경 | 각 10회 | 거리 유효성·방향·잘못된 품질 good 여부 |
| 나란히 / 반대방향 동시 통행 | 각 10회 | 지원 밖 조건으로 분리 보고. 정확한 계수를 보장하지 않음 |
| Wi-Fi 5분 단절 후 복구 | 3회 | NVS 큐, 원래 발생시각, 중복 없이 재전송, 연결 표시 복구 |
| 전송 직후 응답 유실·재부팅 | 10회 | 서버 UNIQUE 키로 1회만 반영, 부팅 ID 변경, 이전 큐 유지 |
| 64건 초과 큐 | 1회 이상 | 새 이벤트 손실과 degraded 노출, 버튼 확인 후 복구 |
| 센서 분리 / NTP 실패 | 각 3회 | fault 또는 2분 후 확인 필요, 여유로 잘못 안내하지 않음 |
| 혼잡 라벨 교정 | 행사 모형 3단계 | 실제 대기열 관찰과 모델 단계 비교, threshold 변경 근거 기록 |
| 전원·배터리 연속 사용 | 행사 운영시간 이상 | 전력계 평균/피크 W, 자동 꺼짐, 실측 지속시간, 발열·고정 상태 |

센서 계수 정밀도 = 방향까지 맞은 이벤트 / 실제 통과 수. 과계수·누락·역방향 오분류를 따로 기록한다. 혼잡 모델은 계수 정확도와 별도로 평가한다. 정확한 내부 인원 측정이라고 발표하지 않는다.

CSV 권장 열: `trial_id,scenario,install_height_mm,roi_a,roi_b,threshold_mm,truth_direction,emitted_direction,event_seq,latency_ms,range_status,notes`.
