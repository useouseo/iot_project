# 센서 도착 전 · 유료 서버 구매 전 준비 상태

지금은 서버를 구매하거나 도메인을 입력할 필요가 없습니다. 현재 PC에서 QR 접속은 사용자가 확인했습니다. 실제 센서 2대 연결과 유료 서버 배포는 아직 하지 않았습니다.

## 지금 사용할 실행 파일

- `start_public_demo.bat`: 센서 없이 가상 데이터와 휴대폰 QR로 화면 시연. 별도 demo DB를 사용합니다.
- `start_public.bat`: 실제 센서용 live DB와 QR. 센서를 등록/연결하기 전 상태는 '확인 필요'가 정상입니다.
- 실행 종료/재실행 후 MariaDB 데이터는 유지됩니다. 임시 주소와 QR은 바뀝니다. 기존 `db_config.json`과 DB를 보존하세요.

## 미리 준비한 서버 구성

`deploy/`는 Ubuntu 24.04 LTS VPS 한 대를 위한 구성입니다. Python 앱, MariaDB 11.4, Caddy HTTPS 프록시를 Docker Compose로 실행합니다. 이 파일들이 GitHub에 있다는 이유만으로 서버가 생성되거나 결제되지는 않습니다.

| 파일 | 역할 |
|---|---|
| `deploy/install.sh` | 구매한 Ubuntu 서버에 Docker 설치, 컨테이너 실행, 백업 타이머 설치 |
| `deploy/configure.py` | 도메인·이메일·최초 관리자 비밀번호 설정 및 DB 비밀번호 자동 생성 |
| `deploy/compose.yaml`, `deploy/Dockerfile` | live 앱과 MariaDB 실행, DB 영구 볼륨, 자동 재시작, 상태 검사 |
| `deploy/Caddyfile` | 고정 도메인 HTTPS 인증서 발급·갱신과 앱 연결 |
| `deploy/backup.sh` | 실행 중인 MariaDB를 압축 SQL로 백업 |
| `deploy/restore.sh` | 명시적으로 확인한 백업으로 DB 복원 |
| `deploy/restflow-backup.*` | 매일 한국 시간 03:00 백업 예약 |
| `deploy/check.sh` | 실제 공개 HTTPS 주소와 live DB 응답 확인 |

서버 DB 포트 3306과 앱 포트 8000은 외부에 게시하지 않습니다. DB 데이터와 인증서는 Docker 영구 볼륨에 보존합니다. Docker 자동 실행과 컨테이너 재시작 정책을 적용합니다. 새 DB의 기본 관리자 비밀번호는 설정한 비밀번호로 교체하며, 기존에 변경한 비밀번호는 재시작 시 덮어쓰지 않습니다.

## 서버를 구매한 뒤에 할 일

1. Ubuntu 24.04 LTS 서버와 고정 공인 IP를 준비합니다. 메모리 1GB는 소규모 시험의 후보이며 실제 부하 검증은 필요합니다. 앱 이미지 빌드 중 메모리가 부족하면 swap 또는 2GB 사양을 검토합니다.
2. 사용할 도메인/서브도메인의 A 레코드를 고정 IP로 연결합니다. 실제 IPv6 연결이 없다면 같은 이름에 잘못된 AAAA 레코드를 두지 않습니다.
3. Lightsail 등 서비스의 방화벽에서 TCP 80/443을 허용하고 SSH 22는 본인 접속에 필요한 범위로 제한합니다. 3306/8000은 개방하지 않습니다.
4. GitHub 최신 소스를 서버의 **`/opt/restflow`**에 놓습니다. 비공개 저장소이므로 본인 GitHub 인증으로 가져오거나, PC에서 GitHub ZIP을 내려받아 압축을 풀고 서버로 복사합니다. GitHub 토큰·SSH 개인키·DB 비밀번호를 채팅에 보내지 않습니다.
5. 서버 SSH 터미널에서 아래 명령을 실행합니다. 예시 도메인과 이메일은 실제 값으로 바꿉니다.

```bash
cd /opt/restflow
sudo bash deploy/install.sh --domain restflow.example.com --email operator@example.com
```

처음에는 서버용 관리자 비밀번호를 두 번 입력합니다. DB 비밀번호는 자동 생성되어 `deploy/.secrets/`에 저장됩니다. 이 디렉터리는 호스트에서 소유자만 접근하고, 컨테이너에는 필요한 파일만 읽기 전용으로 연결합니다. 기존 비밀번호 파일이 있으면 재생성하지 않습니다. `deploy/.env`에는 도메인과 이메일만 저장합니다.

6. DNS 반영과 인증서 발급을 기다린 뒤 아래 확인을 실행합니다.

```bash
sudo bash deploy/check.sh
```

설치 명령이 끝났다는 사실만으로 외부 HTTPS 접속이 확인된 것은 아닙니다. `check.sh`가 통과하고 휴대폰 LTE/5G에서 실제 접속되는지 확인해야 합니다. 인증서 발급은 실제 DNS·네트워크·인증기관 상태에 따라 실패할 수 있습니다.

7. `https://본인도메인/admin`에 접속해 로그인하고 QR을 생성합니다. 같은 고정 도메인을 유지하면 재시작/재배포 후에도 기존 QR을 계속 사용할 수 있습니다.
8. 센서 2대 각각에 고유 장치 ID·토큰을 넣고, 같은 고정 HTTPS API_BASE와 해당 인증서를 검증할 ROOT_CA를 설정합니다. 기기가 도착하면 실제 업로드·통행 검출·수신을 검증합니다. 인증서 검증을 끄지 않습니다.

## PC 데이터를 서버로 옮길 때

PC MariaDB와 서버 MariaDB는 서로 다른 DB입니다. 자동으로 동기화되지 않습니다. PC의 시설·장치 토큰·지도·관리자 비밀번호까지 유지하려면 SQL 백업을 서버로 복원해야 합니다. 백업에는 민감한 데이터가 포함되므로 GitHub에 올리지 않습니다.

PC MariaDB의 live DB 이름이 `restflow`인 경우의 예시입니다. 다른 이름이면 DB 이름 매핑을 먼저 확인해야 합니다. `-p` 뒤에 실제 비밀번호를 붙이지 말고 프롬프트로 입력합니다.

```text
mariadb-dump -u 본인DB사용자 -p --single-transaction --routines --events --add-drop-database --databases restflow > restflow-pc.sql
```

`restflow-pc.sql`을 gzip으로 압축해 서버로 안전하게 복사하고, 서버에서 아래 복원 명령을 사용합니다. 다른 버전의 MariaDB에서 만든 덤프는 복원 후 확인이 필요합니다. 복원한 DB에 이미 변경한 관리자 비밀번호가 있으면 그 비밀번호로 로그인합니다. 서버 설치 때 정한 초기 비밀번호로 자동 초기화되지 않습니다.

## 백업·복원·재시작

아래 명령은 구매한 서버에서 실행합니다.

```bash
# 수동 백업 (운영 중에도 가능)
sudo bash /opt/restflow/deploy/backup.sh

# 예약 확인: UTC 18:00 = 한국 시간 다음 날 03:00
sudo systemctl list-timers restflow-backup.timer

# 백업 작업 로그
sudo journalctl -u restflow-backup.service -n 30

# 상태 및 재시작
cd /opt/restflow/deploy
sudo docker compose ps
sudo docker compose restart
```

백업은 `deploy/.backups/`에 저장하고 약 2주 지난 백업은 정리합니다. **같은 서버의 백업이므로 서버 삭제·디스크 손실까지 보호하지는 않습니다.** 중요한 백업은 PC나 별도 저장소로 복사해야 합니다. 복원은 잠깐 앱을 중지하고 기존 `restflow` DB를 교체합니다. 먼저 현재 데이터를 백업한 뒤 실행하세요.

```bash
sudo bash /opt/restflow/deploy/restore.sh /안전한경로/백업.sql.gz --confirm-replace
```

업데이트할 때 `/opt/restflow` 안에서 소스를 갱신하고 `deploy/.env`, `deploy/.secrets`, `deploy/.backups`와 Docker 볼륨은 유지합니다. 갱신 전 수동 백업을 권장합니다.

```bash
cd /opt/restflow/deploy
sudo docker compose up -d --build --wait --wait-timeout 240
sudo bash check.sh
```

**`docker compose down -v`는 DB와 인증서 볼륨을 삭제하므로 운영 중 사용하지 마세요.**

## 아직 확인할 수 없는 부분

- 센서가 오지 않았으므로 실물 기기 2대 연결, 감지 정확도, 전원/배터리, 현장 Wi-Fi는 미검증입니다.
- 서버를 구매하지 않았으므로 실제 Lightsail 환경, 공인 DNS/인증서 발급, 서버 재부팅 시 systemd 타이머 실행은 미검증입니다.
- 테스트 환경의 컨테이너 재시작/HTTPS/DB 보존/백업 복원 검증은 실제 VPS 운영 검증과 구분합니다.
