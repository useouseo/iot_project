# 공간별 실내·야외 운영 버전 — 변경 사항

수정일: **2026-11-13 (KST)**

기준 브랜치: `design/restflow-update-2026-11-10`

개발 브랜치: `feature/outdoor-tmap-navigation`

화면·서버 버전: **`spaces-v1`**

2026-11-10 수정본 이후 추가·변경한 기능을 정리했습니다. 이전 변경 내역은 [2026-11-10 변경 사항](CHANGES-2026-11-10.md), 설치·실행 순서는 [공동 개발자 실행 안내](TEAM_SETUP.md)를 참고하세요.

## 1. 공간별 독립 운영

- 관리자 상단에서 공간 목록을 선택하고 공간을 추가·삭제할 수 있습니다.
- 공간을 만들 때 **이름과 실내 / 야외 유형**을 정합니다. 새 공간은 화장실·장치·배치도가 없는 상태로 시작하며, 운영 유형은 생성 후 고정됩니다.
- 화장실·운영 칸 수·지도·위치·센서 연결·혼잡도·QR을 공간별로 분리합니다.
- 다른 공간의 화장실을 수정·삭제·연결·초기화하거나 통행 이력을 조회하지 못하도록 서버에서 소속을 검사합니다.
- 관리자 선택은 `/admin?festival_id=...`에 담습니다. 탭마다 다른 공간을 관리할 수 있고, 공유 서버에 하나의 ‘현재 공간’을 저장하지 않습니다.

## 2. 야외 지도와 보행 경로

- **TMAP 실제 지도**를 추가했습니다. HTTPS 페이지에서 위치 권한을 허용하면 내 위치와 오차 범위를 표시합니다.
- 관리자는 화장실 입구를 등록하고 마커를 드래그해 수정할 수 있습니다. 위치가 없는 화장실을 선택하면 지도 중앙에 반투명 마커를 표시합니다.
- 방문객이 지도 마커를 눌러 화장실을 선택하고 길찾기를 요청하면 **TMAP 보행자 API의 경로·거리·예상 시간**을 표시합니다.
- SDK 레이어가 터치를 가로채는 상황을 보완하고, 지도 이동 제스처와 마커 탭을 구분합니다.
- `내 위치 확인`과 `길찾기` 두 버튼을 유지합니다. 경로가 나오면 같은 버튼이 `경로 지우기`로 바뀌고, 경로를 지우거나 다른 화장실을 선택하면 다시 `길찾기`가 됩니다.

### 위치 확인 보완

- `내 위치 확인`을 누르면 캐시 없이 위치를 새로 요청합니다.
- 오래된 위치는 길찾기 전에 자동으로 다시 확인합니다.
- 오차가 크거나 최신 위치를 받지 못하면 출발 위치를 확인하고 마지막 위치로 계속할지 묻습니다.
- 위치 권한을 거절하면 길찾기를 진행하지 않습니다. 위치는 DB에 저장하지 않고 경로 요청 시 TMAP에 전달합니다.
- 음성 안내·자동 재탐색은 포함하지 않습니다. 이동 후 버튼으로 다시 조회할 수 있으며, 임시 통로·출입 통제는 현장 확인이 필요합니다.

## 3. 공간별 전용 QR

- 선택한 공간의 `/f/고유식별자` 주소로 QR을 생성합니다. 공간마다 별도 QR을 사용합니다.
- 관리자가 다른 공간을 선택해도 기존 QR로 들어온 방문객은 해당 공간 화면을 계속 봅니다.
- PNG / SVG 다운로드를 유지하고 파일 이름에 공간 ID를 넣습니다.
- 고유 식별자는 재시작 후에도 유지됩니다. 고정 도메인에서는 QR을 계속 사용할 수 있지만, **Quick Tunnel의 공개 도메인이 바뀌면 QR을 다시 생성**해야 합니다.
- 예전 `/` 주소는 기존 공간(1번)에 연결해 호환성을 유지합니다.

## 4. 공간 삭제

- 상단 **추가 옆 삭제** 버튼을 제공합니다. 이름 입력 없이 **정말 삭제할까요?** 확인창만 표시합니다.
- 삭제한 공간은 관리자 목록에서 제거하고 다른 공간으로 이동합니다.
- 기존 QR과 열려 있던 방문객 화면에는 **안내 종료**를 표시합니다. 삭제한 공간의 상태 API는 HTTP 410을 반환하고 장치 이벤트 수신을 거절합니다.
- 지도·화장실·장치·통행 기록은 삭제하지 않고 보관합니다. 장치 ID도 기록에 남으므로 새 연결에는 다른 ID를 사용합니다.
- 동시 삭제 요청에서도 마지막 공간 하나는 남도록 보호합니다.
- 1번 기존 공간을 삭제해도 관리자 접속·새 공간 추가·화면 파일 제공은 유지되며, 재시작해도 삭제한 공간이 다시 나타나지 않습니다.

## 5. 기존 데이터 이전과 호환성

- `festivals` 테이블과 `toilets.festival_id`, 삭제 상태를 위한 `festivals.active`를 추가합니다. 내부 이름과 기존 주소 형식은 호환성을 위해 유지합니다.
- 기존 등록 정보는 **기존 공간**에 묶어 보존합니다. 관리자 비밀번호·장치 토큰·통행 기록·배치도·위도/경도·이미지 X/Y를 지우지 않습니다.
- 시스템 기본 이름 `기존 축제`만 `기존 공간`으로 바꾸고, 직접 입력한 이름은 유지합니다.
- 실사용 `restflow`와 시연 `restflow_demo` DB는 계속 분리합니다. 시연 모드는 실내·야외 유형과 별개입니다.
- 관리자 로그인·비밀번호 변경, 장치 토큰 인증, 센서 이벤트·하트비트 API와 펌웨어의 기본 수신 방식을 유지합니다.

## 6. 실행·지도 로딩 보완

- 키 입력칸이 비어 있는 **`start_with_tmap.bat`**를 추가했습니다. 키를 한 번 넣고 저장하면 더블클릭으로 시연 모드를 실행할 수 있습니다.
- TMAP 지도와 보행자 경로의 키 설정을 분리했습니다. 같은 키에 두 기능 권한이 있으면 같은 값을 사용할 수 있습니다.

| 설정 | 용도 |
|---|---|
| `RESTFLOW_TMAP_MAP_KEY` | 브라우저 지도 표시 |
| `RESTFLOW_TMAP_ROUTE_KEY` | 서버 보행자 경로 조회 |

실제 키는 GitHub에 넣지 않고 카톡방에서 별도로 공유합니다. 서버 키는 `RESTFLOW_TMAP_ROUTE_KEY_FILE`로 파일에서 읽을 수도 있습니다. Docker 배포는 `deploy/.env`에 값을 추가한 뒤 앱을 다시 생성합니다. configure.py 재실행 시에는 TMAP 값을 보존해야 합니다.

- SDK 로딩 방식, HTTP 지도 타일의 HTTPS 전환, 지도 높이 문제를 수정했습니다.
- 지도 키가 없거나 API 요청이 실패하면 설정·연결 안내를 표시합니다. API 제공자 측 이용 권한·도메인 제한·요금·호출 한도를 확인해야 합니다.
- 서버는 초당 1회와 동시 요청 제한을 적용합니다.
- 버전이 붙은 화면 파일 주소, `/api/version`, 실행 창의 버전·폴더 출력을 추가해 이전 파일 실행 여부를 확인할 수 있습니다.

## 업데이트 방법

1. 기존 서버를 `Ctrl+C`로 종료하고 DB 백업을 보관합니다.
2. 같은 실행 폴더의 **`server.py`와 `web`을 함께 교체**합니다.
3. `db_config.json`, `.runtime`, 개인 키를 넣은 `start_with_tmap.bat`는 보존합니다.
4. 재실행 후 브라우저를 새로고침하고, 관리자 화면의 **화면·서버 버전: spaces-v1**을 확인합니다.

공간 구분을 모르는 이전 서버 버전을 같은 DB에 연결하지 마세요. 첫 설치와 실행은 [공동 개발자 실행 안내](TEAM_SETUP.md)를 참고하세요.

## 검증 범위

- 실제 MariaDB 11.8의 분리된 시험 DB에서 **Python 검사 75개 통과**.
- 기존 데이터 이전·재시작 보존, 기본 이름 변경과 사용자 이름 보존, 장치 토큰·기록·로그인 유지, 공간별 조회/변경 제한, QR, 동시 요청 분리, 삭제·안내 종료와 마지막 삭제 보호를 확인했습니다.
- 실제 DB를 사용하는 Playwright에서 공간 생성부터 지도·화장실·센서·QR 등록, 방문객 고정 접속, 저장·취소, 삭제 확인과 재접속을 확인했습니다.
- 별도 브라우저 검사에서 모바일 마커 선택, 위치 재시도·시간 초과·권한 거절, 버튼 전환과 화면 넘침을 확인했습니다. Python·JavaScript 문법 검사도 통과했습니다.

브라우저 검사의 TMAP/GPS는 대체 응답입니다. 실제 키 인증·지도 타일·현장 경로·실기기 위치·실제 센서·동료 PC의 Windows 실행·운영 서버 배포는 별도로 확인해야 합니다.

### 개발 검사 실행

생성·삭제 권한이 있는 분리된 MariaDB 시험 DB를 준비하고 `RESTFLOW_TEST_DB_CONFIG` / `RESTFLOW_DB_CONFIG`로 연결 설정을 지정합니다. 실사용 DB에서 테스트하지 않습니다. 전체 브라우저 검사는 별도 `_browser_test` DB를 사용합니다.

```text
python -m unittest discover -s tests -v
python tools/festivals_smoke.py
python tools/outdoor_smoke.py
python tools/location_smoke.py
node --check web/app.js
node --check web/outdoor.js
```
