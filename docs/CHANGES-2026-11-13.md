# 공간별 실내·야외 운영 버전 — 변경 사항

수정일: **2026-11-13 (KST)**

기준 브랜치: `design/restflow-update-2026-11-10`

개발 브랜치: `feature/outdoor-tmap-navigation`

화면·서버 버전: **`spaces-v1`**

2026-11-10 디자인 수정본 이후의 기능과 화면 변경을 정리했습니다. 이전 변경 내역은 [2026-11-10 변경 사항](CHANGES-2026-11-10.md), 공동 개발자 실행 방법은 [공동 개발 실행 안내](TEAM_SETUP.md)를 참고하세요.

## 1. 공간별 독립 운영

- **공간 목록·추가·삭제:** 관리자 상단에서 관리할 공간을 선택하고 여러 공간을 운영할 수 있습니다.
- **생성 시 이름과 유형 선택:** `새 공간 추가`에서 이름을 입력하고 **실내 / 야외**를 선택합니다. 새 공간은 화장실·장치·배치도가 없는 상태로 시작합니다.
- **데이터 분리:** 화장실 이름·운영 칸 수·지도·위치·센서 연결·혼잡도·QR을 공간별로 관리합니다. 다른 공간의 화장실을 수정·삭제·연결·초기화하거나 통행 이력을 조회하지 못하도록 서버에서도 소속을 검사합니다.
- **관리자 선택과 방문객 접속 분리:** 관리자 선택은 `/admin?festival_id=...`, 방문객은 `/f/고유식별자`에 연결됩니다. 관리자가 다른 공간을 선택해도 기존 QR로 들어온 방문객 화면은 바뀌지 않습니다. 관리자 탭마다 다른 공간을 열 수도 있습니다.
- **유형 고정:** 실내·야외 유형은 생성할 때 정합니다. 다른 유형으로 운영하려면 새 공간을 추가합니다.

## 2. 야외 지도와 보행 경로

- 기존 이미지 배치도 외에 **TMAP 실제 지도**를 지원합니다.
- 방문객이 HTTPS 페이지에서 위치 권한을 허용하면 **내 위치와 오차 범위**를 표시합니다.
- 관리자는 화장실 입구를 지도에 등록하고, 마커를 드래그해 수정할 수 있습니다. 미등록 시설을 선택하면 지도 중앙에 반투명 마커를 보여줍니다.
- **화장실 선택 → 길찾기:** TMAP 보행자 경로 API로 경로 선·거리·예상 시간을 표시합니다.
- **같은 버튼에서 전환:** 경로가 표시되면 `길찾기`가 `경로 지우기`로 바뀝니다. 경로를 지우거나 다른 화장실을 선택하면 다시 `길찾기`가 됩니다. `내 위치 확인`과 합쳐 항상 버튼 두 개만 표시합니다.
- **마커 직접 선택:** 방문객도 지도 마커를 눌러 선택할 수 있습니다. SDK 레이어가 터치를 가로채는 상황을 보완하고 지도 이동 제스처와 탭을 구분합니다.

### 위치 확인 처리

- `내 위치 확인`을 누르면 지도 중심만 옮기지 않고 **캐시 없이 위치를 새로 요청**합니다.
- 오래된 위치는 길찾기 전에 자동으로 다시 확인합니다.
- 오차가 크거나 최신 위치를 받지 못했을 때에는 출발 위치를 확인하고 마지막 위치로 계속할지 묻습니다.
- 위치 권한을 거절하면 길찾기를 진행하지 않습니다. 위치는 DB에 저장하지 않고 경로 요청 시 TMAP에 전달합니다.
- 음성 안내와 자동 재탐색은 포함하지 않습니다. 임시 통로·출입 통제는 지도 서비스에 없을 수 있어 현장 확인이 필요합니다.

## 3. 실내 지도와 위치 저장 방식 통일

- 실내는 기존처럼 **배치도 업로드 + 이미지 위 마커 배치 + 혼잡도**를 사용합니다. TMAP 지도와 GPS는 불러오지 않습니다.
- 실내·야외 모두 지도 아래 **위치 저장 / 위치 되돌리기** 바를 표시합니다.
- **오른쪽 정보 저장:** 화장실 이름과 운영 칸 수만 저장합니다.
- **지도 아래 위치 저장:** 실내는 이미지 X/Y, 야외는 입구 위도·경도만 저장합니다.
- 이름을 수정 중이어도 위치만 저장할 수 있고, 정보 저장으로 아직 저장하지 않은 마커 위치가 확정되거나 사라지지 않습니다.
- 자동 갱신 중에도 임시 위치를 유지하며, 다른 공간·시설로 이동할 때 저장하지 않은 변경을 확인합니다.

## 4. 공간별 전용 QR

- 선택한 공간의 고유 주소로 QR을 생성합니다. 공간마다 서로 다른 QR을 사용합니다.
- 기존 **PNG / SVG 다운로드**를 유지하고 파일 이름에 공간 ID를 넣습니다.
- 고유 식별자는 DB에 보존되므로 재시작해도 바뀌지 않습니다. 단, **Quick Tunnel 재실행으로 공개 도메인이 바뀌면 QR을 다시 생성**해야 합니다.
- 예전 `/` 방문객 주소는 기존 공간(1번)으로 연결해 호환성을 유지합니다.

## 5. 공간 삭제

- 상단 **추가 옆 삭제** 버튼으로 선택한 공간을 삭제합니다.
- 이름 입력 없이 **정말 삭제할까요?** 확인창만 표시합니다.
- 삭제한 공간은 관리자 목록에서 제거하고, 기존 QR과 열려 있던 방문객 화면에는 **안내 종료**를 표시합니다.
- 센서 수신을 거절하지만 지도·화장실·장치·통행 기록은 삭제하지 않고 보관합니다.
- **마지막 공간 하나는 삭제하지 못하도록 보호**합니다. 동시 삭제 요청에도 마지막 공간이 남도록 DB에서 검사합니다.
- 1번 기존 공간을 삭제해도 관리자 접속·새 공간 추가·화면 파일 제공이 계속 동작합니다. 삭제된 공간이 재시작 후 다시 나타나지 않습니다.

## 6. 화면과 용어 정리

- 축제·행사장에 한정된 문구를 **공간** 기준으로 바꿨습니다. 공원·학교·쇼핑몰·전시장 등에도 같은 화면을 사용할 수 있습니다.
- `새 축제 추가 / 축제 이름 / 축제 만들기` → **새 공간 추가 / 공간 이름 / 공간 만들기**.
- `행사장 지도 / 행사장 배치도 변경` → **지도 / 배치도 변경**.
- 상단 버튼은 **목록 / 추가 / 삭제**로 간단히 표시하고 높이·여백·중앙선을 맞췄습니다.
- 관리자는 지도 제목을 위에, 정보·추가 카드를 오른쪽에 배치합니다. 불필요하게 길어진 정보 카드의 빈 공간을 줄였습니다.
- 마커는 **A·B·C와 혼잡도**를 표시하는 핀 형태로 맞췄습니다.
- 방문객 화면에서는 지도 아래 중복 상세정보, 하단 안내·새로고침·기술 버전 표시를 숨겼습니다. 관리자 화면에서는 버전을 확인할 수 있습니다.

## 7. 데이터 이전과 호환성

- `festivals` 테이블과 `toilets.festival_id`, 삭제 상태를 위한 `festivals.active`를 추가합니다. 내부 이름과 기존 `/f/...` 주소 형식은 호환성을 위해 유지합니다.
- 기존 등록 정보는 **기존 공간** 하나에 묶어 보존합니다. 관리자 비밀번호·장치 토큰·통행 기록·배치도·위치는 지우지 않습니다.
- 시스템 기본 이름 `기존 축제`만 `기존 공간`으로 바꿉니다. 사용자가 직접 만든 공간 이름은 유지합니다.
- 실사용 `restflow`와 시연 `restflow_demo` DB는 계속 분리합니다. 시연 모드는 실내·야외 유형과 별개입니다.
- 관리자 로그인·비밀번호 변경, 장치 토큰 인증, 센서 이벤트·하트비트 API, 펌웨어의 기본 수신 방식은 유지합니다.
- **소스 파일만 공유하면 DB 데이터는 함께 전달되지 않습니다.** 공동 개발자는 각자 MariaDB 설정과 데이터를 사용합니다. 같은 TMAP 키를 사용해도 DB는 공유되지 않고 API 이용량만 같은 한도를 사용합니다.

## 8. 실행·로딩 보완

- 키 입력칸이 비어 있는 **`start_with_tmap.bat`**를 추가했습니다. 키를 한 번 넣고 저장하면 더블클릭으로 시연 모드를 실행할 수 있습니다.
- 지도용 키와 서버 경로용 키를 설정으로 분리했습니다. 실제 키는 GitHub에 올리지 않고 카톡방에서 별도 공유합니다.
- TMAP SDK 로딩 방식, HTTP 지도 타일의 HTTPS 전환, 지도 높이 문제를 수정했습니다.
- 버전이 붙은 화면 파일 주소, 관리자 화면의 `화면·서버 버전`, `/api/version`, 실행 창의 버전·폴더 출력을 추가해 이전 파일 실행 여부를 확인할 수 있습니다.

## 업데이트할 때

1. 기존 서버 실행 창에서 `Ctrl+C`로 종료하고 DB 백업을 보관합니다.
2. **같은 실행 폴더의 `server.py`와 `web`을 함께 교체**합니다. 공동 개발용 실행 안내와 검사 도구가 필요하면 `docs`와 `tools`도 갱신합니다.
3. `db_config.json`, `.runtime`, 개인 키를 넣은 `start_with_tmap.bat`는 보존합니다.
4. 다시 실행하고 브라우저를 새로고침합니다. 관리자 지도 아래 **화면·서버 버전: spaces-v1**을 확인합니다.

업데이트 후에는 공간 구분을 모르는 이전 버전을 같은 DB에 연결하지 마세요. 상세 실행 순서는 [공동 개발 실행 안내](TEAM_SETUP.md)에 있습니다.

## 검증 범위

- 실제 **MariaDB 11.8**의 분리된 시험 DB에서 Python 검사 **75개 통과**.
- 기존 스키마 이전, 기본 이름 변경과 사용자 이름 보존, 토큰·기록·로그인 유지, 공간별 조회/변경 제한, 전용 QR, 동시 요청 분리, 삭제/안내 종료, 동시 마지막 삭제 보호, 정보/위치 독립 저장 확인.
- 실제 MariaDB를 사용하는 Playwright에서 공간 생성부터 지도·화장실·센서·QR 등록, 방문객 고정 접속, 실내 위치 바 저장/되돌리기, 상단 삭제 확인/취소, 재접속 보존 확인.
- 별도 브라우저 검사로 마커 드래그, SDK 레이어를 통한 모바일 탭 선택, 위치 재시도·시간 초과·권한 거절, 버튼 전환, 헤더 정렬과 모바일 넘침을 확인했습니다.
- Python·JavaScript 문법 및 변경 파일 형식 검사 통과.

브라우저 검사에서는 **TMAP/GPS를 대체 응답으로 사용**했습니다. 실제 키 인증·지도 타일·현장 경로·실기기 위치 정확도, 실제 센서, 동료 PC의 Windows 실행 및 운영 서버 배포는 별도 확인이 필요합니다.
