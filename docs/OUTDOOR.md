# 축제별 실내·야외 운영

관리자 상단 **목록**에서 축제를 고르고 **추가**로 이름과 운영 유형을 정합니다. 새 축제의 화장실·장치·배치도는 비어 있습니다. 운영 유형은 생성 후 바꾸지 않습니다. 다른 유형으로 운영하려면 새 축제를 추가하세요. 시연 모드는 가상 센서 데이터 여부로 축제 유형과 별개입니다.

- **야외**: TMAP 실제 지도, 휴대폰 위치, 입구 마커 드래그, 보행 경로.
- **실내**: PNG/JPEG 배치도 업로드, 이미지 위 마커 드래그, 혼잡도. TMAP SDK/GPS는 불러오지 않습니다.
- 화장실 이름·칸 수·위치·혼잡도·센서 연결·배치도는 축제별로 분리됩니다. 한 장치 ID를 서로 다른 축제에 중복 등록할 수 없습니다.
- 지도 마커를 누르면 해당 화장실을 선택합니다. 야외 버튼은 **내 위치 확인 + 길찾기** 두 개이고, 경로가 나오면 같은 버튼이 **경로 지우기**로 바뀝니다.

## 기존 정보 이전 및 업데이트

기존 DB에 `festivals`와 화장실의 `festival_id`를 추가하고 기존 데이터는 **기존 축제** 한 곳에 보존합니다. 지도·이전 실내/야외 선택·이미지 X/Y·실제 위도/경도·장치 토큰·기록·관리자 비밀번호를 지우지 않습니다. 마이그레이션은 다시 시작해도 기존 축제의 공개 식별자를 바꾸지 않습니다.

업데이트 전 실행 중인 서버를 종료하고 DB 백업을 보관하세요. **server.py와 web 폴더를 함께 업데이트**한 후 실행합니다. 화면 아래 **화면·서버 버전: festivals-v3**와 시작 창의 실행 폴더를 확인할 수 있습니다. `db_config.json`, `.runtime`, 키를 입력한 `start_with_tmap.bat`는 보존하세요.

업데이트 후에는 축제 구분을 모르는 이전 버전 서버를 같은 DB에 연결하지 마세요. 라이브와 시연 DB는 이전과 같이 별도입니다.


## 축제 삭제

상단에서 삭제할 축제를 선택하고 **추가 옆의 삭제**를 누릅니다. “정말 삭제할까요?” 확인창에서 확인을 누르면 삭제합니다. 이름을 입력할 필요는 없습니다. 관리자 목록에서 제거하고 다른 축제로 이동합니다. 마지막 축제는 삭제할 수 없으므로 먼저 다른 축제를 추가하세요.

삭제한 축제의 QR은 HTTP 410과 함께 운영 종료 안내를 표시합니다. 이미 열려 있는 방문객 화면도 다음 갱신에 종료 안내로 바뀝니다. 장치 이벤트 수신은 거절하며 지도·화장실·장치·통행 기록은 삭제하지 않고 보관합니다. 재시작해도 삭제한 축제가 다시 나타나지 않습니다. 삭제된 장치 ID는 기록에 남으므로 새 연결에는 다른 장치 ID를 사용합니다.

## 축제별 QR

**방문객 QR** 메뉴에서 현재 선택한 축제 전용 QR을 만듭니다. 주소는 `/f/축제고유식별자`이며 관리자 선택과 무관하게 그 축제의 화면을 보여줍니다. 예전 `/` 주소는 기존 축제(1번)에 연결해 호환성을 유지합니다.

관리자 선택은 `/admin?festival_id=숫자`에 담기므로 관리자 탭마다 다른 축제를 관리할 수 있습니다. 서버에 모든 방문객이 공유하는 ‘현재 축제’를 저장하지 않습니다. API는 요청의 축제 ID와 대상 화장실 소속을 확인합니다.

고정 도메인에서는 같은 축제 QR을 계속 사용할 수 있습니다. Cloudflare Quick Tunnel을 다시 실행해 **공개 도메인이 바뀌면 QR도 다시 생성**해야 합니다. `/api/version`으로 실행 파일 해시를 확인할 수 있습니다(키는 반환하지 않습니다).

## TMAP 설정

TMAP Open API에서 JavaScript 지도와 보행자 경로 API의 이용 권한·현재 제공량/요금·허용 도메인을 확인합니다.

- `RESTFLOW_TMAP_MAP_KEY`: 브라우저 지도 키. 브라우저에 공개되므로 서비스의 허용 도메인 제한을 적용합니다.
- `RESTFLOW_TMAP_ROUTE_KEY`: 서버 보행자 키. 브라우저에는 전달하지 않습니다. `_FILE` 환경변수로 파일에서 읽을 수도 있습니다.

키를 코드나 GitHub에 저장하지 마세요. 같은 키에 두 기능 권한이 있으면 두 변수에 같은 값을 넣습니다.

```bat
set "RESTFLOW_TMAP_MAP_KEY=지도용_키"
set "RESTFLOW_TMAP_ROUTE_KEY=보행자_API_키"
start_public_demo.bat
```

또는 `start_with_tmap.bat`의 빈 키 항목에 값을 넣고 저장한 뒤 더블클릭합니다. 개인 키가 들어간 파일은 공유하지 않습니다. Docker 배포에서는 `deploy/.env`에 두 변수를 추가한 뒤 앱을 다시 생성합니다. configure.py가 .env를 다시 쓰므로 재설정 시 TMAP 값을 보존하세요.

## 지도 및 위치 편집

1. 관리할 축제를 선택한 뒤 **화장실·지도 관리**에서 화장실을 추가합니다.
2. 야외에서는 지도 중앙의 반투명 마커를 실제 입구로 끌어서 **위치 저장**을 누릅니다. 위치가 있는 마커도 드래그로 수정할 수 있습니다.
3. 실내에서도 배치도를 올리고 마커를 드래그한 뒤 지도 아래 **위치 저장**을 누릅니다. **위치 되돌리기**로 취소할 수 있습니다. 오른쪽 **변경사항 저장**은 이름·칸 수만 저장합니다.
4. **장치 관리**에서 선택한 축제의 화장실에 장치를 등록합니다.
5. 전용 QR로 방문객 화면에 접속해 표시와 경로를 확인합니다.

야외 위치는 저장 전 **위치 되돌리기**로 취소할 수 있고, 5초 자동 갱신에도 임시 위치를 유지합니다. 좌표가 없는 시설은 방문객 실제 지도에 표시하지 않습니다. 관리자의 편집 화면은 지도 제목을 위에 두고 오른쪽 설정·추가 카드를 내용 높이에 맞춰 배치합니다.

## 위치·길찾기 제한

HTTPS와 사용자 위치 권한이 필요합니다. 내 위치 확인은 매번 캐시 없이 새 위치를 요청합니다. 오래된 위치는 경로 요청 전 갱신하고, 오차가 크거나 갱신에 실패하면 출발점을 확인한 뒤 마지막 위치로 계속할지 묻습니다. 권한 거절 시에는 진행하지 않습니다. 위치는 DB에 저장하지 않고, 길찾기 시 출발 좌표를 TMAP에 전달합니다.

음성 안내·자동 재탐색은 포함하지 않습니다. 이동 후 다시 길찾기를 조회할 수 있습니다. 행사장의 임시 통로·통제 구간은 지도 서비스에 없을 수 있어 현장 확인이 필요합니다. 지도/보행자 API 키가 없으면 안내를 표시합니다. API 제공자 측 호출 한도를 설정하세요. 서버는 초당 1회 및 동시 요청 제한을 적용합니다.

## 개발 검사

MariaDB와 생성·삭제 가능한 **분리된 시험 DB** 권한을 준비합니다. 실사용 DB에서 테스트하지 않습니다.

```text
python -m unittest discover -s tests -v
python tools/festivals_smoke.py
python tools/outdoor_smoke.py
python tools/location_smoke.py
node --check web/app.js
node --check web/outdoor.js
```

`RESTFLOW_TEST_DB_CONFIG`/`RESTFLOW_DB_CONFIG`로 시험 연결 설정을 지정합니다. 전체 브라우저 검사는 실제 MariaDB의 별도 `_browser_test` DB에서 축제 생성·독립 목록·센서·QR·방문객 고정 접속·재시작을 확인합니다. TMAP과 GPS는 대체 응답으로 검사하므로 실제 인증·타일·현장 경로와 휴대폰 위치 검증은 별도로 필요합니다.

실내 위치 저장과 화장실 정보 저장은 별도 API로 처리합니다. 이름을 수정 중이어도 위치만 저장할 수 있으며, 정보 저장으로 저장 전 마커 위치가 확정되거나 사라지지 않습니다.
