# 현재 버전 시연 순서

## 센서가 없는 지금

1. PC의 MariaDB 서비스를 켜고 **`start_public_demo.bat`를 더블클릭**합니다.
2. 처음이면 DB 접속정보와 관리자 비밀번호를 설정합니다. 이미 설정했다면 그 비밀번호를 사용합니다.
3. 자동으로 열린 관리자 화면에 로그인합니다. 방문객 화면에는 가상 시연 표시가 있습니다.
4. **QR 생성**을 누르고 휴대폰 LTE/5G로 스캔해 실제 화면이 열리는지 확인합니다. 주소를 직접 입력하지 않습니다.
5. 지도에서 시설을 선택하고 여유/보통/혼잡 또는 수신 단절 시 ‘확인 필요’를 보여줍니다.
6. 관리자에서 시설명·운영 칸 수·지도 위치를 저장하고 방문객 화면에 반영되는지 확인합니다.
7. ‘시연 통행 데이터 추가’로 가상 기록을 갱신하고 최근 통행 추이를 확인합니다.

검은 실행 창과 PC 인터넷을 시연이 끝날 때까지 유지합니다. 재실행하면 QR을 다시 생성합니다. 가상 데이터를 실제 센서 측정 결과라고 발표하지 않습니다. 이 모드는 별도 `restflow_demo` DB를 사용합니다.

## 실제 센서 2대가 도착한 뒤

1. **`start_public.bat`**로 live DB를 실행합니다.
2. 두 화장실에 각각 다른 장치 ID를 등록해 토큰을 발급합니다.
3. 각 기기의 Wi-Fi, 공개 HTTPS API_BASE, ID·토큰, ROOT_CA를 설정하고 빌드·업로드합니다.
4. 기기별 수신 상태, 입장/퇴장 방향, 중복 재전송, 연결 단절·복구를 확인합니다.
5. 관리자에서 QR을 생성해 실제 수신 데이터가 휴대폰에 표시되는지 확인합니다.

임시 공개 주소를 재발급받으면 QR뿐 아니라 기기의 API_BASE도 바꿔야 합니다. 실제 기기 시험은 아직 하지 않았습니다. 제안 시험은 [검증 기록](VALIDATION.md)에 있습니다.

## 유료 서버를 구매한 뒤

[배포 준비 안내](배포준비.md)에 따라 고정 IP·도메인·HTTPS·DB·자동 실행·백업을 적용하고 실제 외부 접속을 확인합니다. 서버에서는 BAT 대신 Docker Compose가 live 모드로 실행됩니다. 고정 주소로 QR을 다시 생성하고 기기 API_BASE를 해당 주소로 변경합니다.

## 발표에서 구분할 내용

- **완료:** MariaDB·관리자·QR 소프트웨어, PC QR 접속, Python 52개 검사, 테스트 환경의 HTTPS·두 가상 장치 전송·재시작·백업/복원.
- **미완료:** 실물 센서 정확도·전원·현장 Wi-Fi, 실제 유료 VPS 적용과 부하 시험.
- 혼잡도는 최근 통행량 기반 추정 단계입니다. 정확한 내부 인원수·대기시간·배터리 잔량은 제공하지 않습니다.
- 두 세트의 부품 구성과 실제 감지 방식은 [하드웨어 안내](HARDWARE.md)를 참고합니다. 가격은 기존 자료의 참고값이며 현재 견적이 아닙니다.
