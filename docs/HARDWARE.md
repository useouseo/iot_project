## 배선

| ATOM Lite Grove | ToF Unit | 비고 |
|---|---|---|
| G26 / SDA | SDA | 펌웨어 SDA_PIN=26 |
| G32 / SCL | SCL | 펌웨어 SCL_PIN=32 |
| GND | GND | 공통 접지 |
| Grove 전원 | Unit VCC | 완제품 Unit의 입력 규격을 실물/제조사 문서로 확인한 뒤 연결 |

Grove 케이블의 색깔만 믿지 말고 양쪽 기판 라벨을 확인한다. VL53L1X **칩/벌크 모듈**과 M5Stack 완제품 Unit의 허용 전원은 동일하다고 가정하지 않는다. 배터리는 ATOM USB-C에 연결하고 센서/ESP32 GPIO에 5V를 직접 주입하지 않는다. Grove Unit 기본 I²C 주소는 0x29이며 세트별 버스가 분리되므로 주소 충돌이 없다.

참조: [ATOM Lite 제조사 문서](https://docs.m5stack.com/en/core/ATOM%20Lite), [M5Stack ToF4M](https://docs.m5stack.com/en/unit/TOF4M), [Pololu VL53L1X 라이브러리](https://github.com/pololu/vl53l1x-arduino). 라이브러리 헤더에서 `setROISize`, `setROICenter`, `readSingle` API를 확인했다. 실제 구매품의 리비전·케이블 포함 여부·치수는 온라인 이미지로 검증하지 않았다.

## 감지 방식과 교정

센서를 출입구 위에서 아래로 향하게 설치하고 광학 영역 A와 B를 **통행 방향을 따라 앞뒤로** 배치한다. 좌우로만 나누면 들어오는 사람과 나가는 사람을 구분하기 어렵다. 센서 장착 방향에 따라 A/B의 의미가 뒤집힐 수 있다.

펌웨어는 4×8 ROI 두 개(초기 중심 SPAD 167, 231)를 번갈아 단발 측정한다. 각 50ms timing budget으로 한 쌍은 최소 약 100ms이며 I²C/처리 오버헤드가 추가된다. 이것은 동시 다중영역 측정이 아니다. 영역 분리, 바닥/머리 반사, 설치 높이, 조명, 모자, 통행 속도로 성능이 달라진다. 중심값은 검증 완료한 설치값이 아니다.

1. 빈 통로에서 A/B 거리와 `range_status`를 기록한다. 센서 커버/보호필름·이물질 확인.
2. 예상 최단·최장 신장에 대해 임계값을 조정한다. 예제 DETECT_MM=1500, RELEASE_MM=1650은 출고 보장값이 아닌 시작값이다. 히스테리시스로 경계 진동을 줄인다.
3. A→AB→B→빈 상태가 입장, 반대가 퇴장이 되도록 장착 방향이나 ROI 중심을 교환한다. 보행 중 겹침 AB가 관측돼야 한다.
4. 불완전 통과, 되돌아감, 3.5초 초과 정지는 무효 처리하고 두 영역이 비워져야 재시작한다. 잘못된 거리 상태도 진행 중 경로를 폐기한다.
5. 한 줄 통행에서 먼저 교정한다. 나란히 통행·동시 역방향·큰 짐·붙어서 통행은 지원 성능을 보장하지 않는다. 빠른 통과에서 상태가 생략되면 보수적으로 계수하지 않는다.

광학 성능이 충분하지 않으면 단순 코드 수정으로 해결된다고 가정하지 않는다. 실제 센서 추가/다른 다중영역 센서/통로 구조 변경은 시험 후 별도 구매 결정이다.

## 펌웨어

`firmware/include/secrets.example.h`를 `secrets.h`로 복사하고 Wi-Fi, HTTPS API_BASE, 등록한 DEVICE_ID/DEVICE_TOKEN, 서버의 신뢰 루트 CA를 설정한다. 예제 값으로는 현장에 연결되지 않는다. `secrets.h`는 Git에서 제외했다. HTTPS 검증을 끄는 옵션은 없다.

```sh
cd /workspace/iot_project/firmware
PLATFORMIO_CORE_DIR=/workspace/.platformio /workspace/.venvs/iot/bin/pio run
PLATFORMIO_CORE_DIR=/workspace/.platformio /workspace/.venvs/iot/bin/pio run --target upload
PLATFORMIO_CORE_DIR=/workspace/.platformio /workspace/.venvs/iot/bin/pio device monitor
```

Wi-Fi/HTTP 전송은 별도 FreeRTOS 태스크로 센서 샘플링을 막지 않는다. NTP 동기화 전 통과는 시각을 꾸며 저장하지 않으며 품질 fault를 전송한다. 장치 네트워크는 NTP(UDP 123), DNS, HTTPS 서버를 허용해야 한다. 클라우드 개발 환경의 프록시 설정을 실물 ESP32에 복사하지 않는다.

부팅 ID+순번으로 이벤트를 식별한다. 최대 64개 대기열을 NVS에 저장하며 전송 실패/재부팅 후 순서대로 재시도한다. 응답을 잃어 재전송해도 서버에서 중복 제거한다. 24시간 초과 대기 이벤트는 폐기하고 손실을 degraded로 표시한다. 큐 초과 시 새 이벤트를 버리고 degraded를 유지한다. 원인 조사 후 ATOM 버튼(G39)을 3초 누르면 품질 경고를 해제한다. 배터리나 잘못된 설정으로 재부팅해도 대기열을 임의 삭제하지 않는다. 잘못된 인증/충돌 이벤트는 반복 재시도되므로 서버 설정과 로그의 HTTP 코드를 확인한다. NVS 매 이벤트 쓰기는 시제품용이며 장기 상시 사용은 쓰기 수명·버퍼 설계를 재검토해야 한다.

## 배터리 검증

5000mAh를 그대로 5V USB 출력의 5000mAh로 계산하면 안 된다. 내부 셀 3.7V라고 가정하면 18.5Wh이며, USB 변환효율 80% 가정 시 사용 가능 에너지는 약 14.8Wh다. **이는 제품 실측치가 아닌 예시 가정이다.** 지속시간 ≈ (실측 사용가능 Wh)/(실측 평균 W). 예컨대 0.8W라면 약 18.5시간이지만 현재 시스템의 측정 결과는 아니다.

USB 전력계로 부팅, Wi-Fi 재접속, 통신 피크와 평균 전력을 측정하고 센서 대기 상태에서도 배터리가 꺼지지 않는지 확인한다. 완충 후 실제 행사 운영시간 이상 연속 기록한다. 구매 부품에 배터리 잔량 게이지가 명시돼 있지 않으므로 웹에 임의 잔량 %를 표시하지 않는다.
