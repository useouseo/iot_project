# 디자인 수정 버전 — 기능 변경 사항

수정일: **2026-11-10 (KST)**  
기준 브랜치: `feature/restflow-prototype-20261105`  
수정 브랜치: `design/restflow-update-2026-11-10`

색상, 글자 크기, 카드 크기, 여백 등의 단순 스타일 변경은 이 문서에서 생략합니다.

## 방문객 화면

- **추천순 정렬 추가:** 운영 칸 수를 반영한 기존 통행량 혼잡 점수가 낮은 시설부터 나열합니다. 기본 정렬은 추천순이며, 전체를 선택하면 시설 순서로 볼 수 있습니다.
- **추정 혼잡도 % 표시:** 혼잡도 지수와 운영 칸 수를 함께 표시하고 추천 시설에 배지를 표시합니다. 연결이 끊겼거나 데이터 신뢰도를 확인할 수 없는 시설은 `%` 대신 `안내 준비 중`으로 표시하며 추천순 뒤쪽에 둡니다.
- **장치 연결 정보 제거:** 방문객에게 센서 연결 개수, 마지막 수신 시각, 센서 상세 정보를 표시하지 않습니다. 기존 `확인 필요` 필터도 제거했습니다. 관리자는 기존처럼 장치 상태와 마지막 수신 정보를 확인할 수 있습니다.
- **지도 상태 글씨:** 지도 마커의 A·B·C 문자와 색상 외에 여유·보통·혼잡 상태를 작은 글씨로 함께 표시합니다.
- **시설이 많을 때 목록 스크롤:** PC에서는 지도 높이를 유지하면서 목록 안에서 스크롤하고, 자동 갱신 후에도 스크롤 위치를 유지합니다. 모바일에서는 페이지 전체를 스크롤합니다.

### 추정 혼잡도 %의 의미

기존 혼잡 점수는 최근 10분 입장량, 입·퇴장 차이, 이전 10분 대비 입장 증가량을 운영 칸 수로 나눈 값입니다. 기존 여유·보통·혼잡 판정 기준은 유지했습니다.

`score`가 `0 / 0.8 / 2 / 4 이상`일 때 `0 / 40 / 75 / 100%`가 되도록 구간별 선형 환산합니다. 유효하지 않은 데이터는 `null`을 반환합니다. API 응답에 `congestion_percent` 필드를 추가했습니다.

이 값은 **통행량 기반 상대 혼잡지수**입니다. 실제 사용 중인 칸의 비율, 대기 인원 또는 대기시간을 뜻하지 않으며, 환산 기준은 현장 데이터에 맞춘 보정이 필요한 기본 참고값입니다.

## 관리자 화면

- **장치와 화장실 연결 표시:** 운영 현황과 장치 관리의 장치 ID 아래에 연결된 화장실 이름을 표시합니다. 예: `demo-1` / `동문 화장실`. 화장실 이름 변경 시 목록에도 반영됩니다.
- **화장실·지도 통합 관리:** 화장실 이름·운영 칸 수와 지도 위치를 함께 저장합니다. 수정 취소와 위치 되돌리기를 제공하며, 저장 버튼은 한 곳으로 통합했습니다.
- **선택한 화장실의 통행량 확인:** 지도 또는 화장실 목록에서 시설을 선택하면 해당 시설의 최근 2시간 그래프를 불러옵니다. 제목에도 시설 이름을 표시합니다. 그래프는 10분 단위 입장+퇴장 통행 횟수이며 전체 화장실 합계가 아닙니다. 다른 시설의 늦은 응답이 현재 그래프를 덮어쓰지 않게 했습니다.

## 기존 운영 방식

MariaDB 구조, 센서 이벤트·하트비트 API, 장치 토큰 인증, 관리자 로그인·비밀번호 변경, 시설 추가·삭제, 배치도 업로드, QR 자동 접속 주소·PNG/SVG 다운로드, 펌웨어 및 기존 실행·배포 방법을 유지합니다. 별도 SQLite 시연 서버나 추가 시연 제어 패널은 포함하지 않습니다.

## 검증 범위

- Chromium에서 추천순, 혼잡도 %, 장치별 시설 이름, 관리자 선택/저장/취소, QR 다운로드, 비밀번호 변경 및 15개 시설 목록 스크롤을 확인했습니다.
- 14개 화면 너비에서 편집 버튼이 박스 밖으로 밀리지 않는지 확인했습니다. 지도 크기를 유지하면서 오른쪽 영역 높이만 맞췄습니다.
- 실제 HTTP 핸들러의 인증, 시설 CRUD, 센서 이벤트·중복 방지, 이력, QR, 계산 구간 초기화는 격리된 테스트 SQLite 어댑터로 확인했습니다.
- 실제 MariaDB 연결, 물리 센서 및 Windows 외부 터널은 이 환경에서 검증하지 못했습니다.

브라우저 검증 도구: `tools/design_smoke.py`, `tools/responsive_smoke.py` (`playwright`와 기존 Python 의존성 필요). 검증에서는 모의 API를 사용하며 실제 운영 DB를 변경하지 않습니다.
